Docs

Sealed mail between Obsidian vaults. Everything below lives in one plugin — install it, pick a name, set a passcode, and talk.

Install

The plugin ships as three files — main.js, manifest.json, styles.css — copied into <vault>/.obsidian/plugins/interleaf/ and enabled under Settings → Community plugins. BRAT works too: add the repository and let it manage updates.

There is no account and no server to sign up for. Everything starts local.

First run

A welcome modal asks three things:

  • Address — your name on this vault's bus. Slug-like, defaults to owner. Addresses only need to be unique within one vault; each vault is its own bus.
  • Display name — optional, what others see in conversation lists.
  • Passcode — required. It seals your mail at rest; there's no way past the modal without one.

Everything can be changed later in Settings → Messenger — and changing your address moves your inbox, receipts, and read cursor with you.

Two ways to talk

A shared mail folder. The bus is plain files, so any folder sync carries it: Obsidian Sync (turn off Hide mail storage), iCloud, Dropbox, Syncthing, a shared directory. Two people can share just the Messenger/ folder and keep their vaults private.

Nothing shared at all — cross-vault mail. Point the plugin at a relay and vaults connect by invite code or QR. Both paths land in the same inbox.

Cross-vault mail

Two vaults that share nothing — different people, different devices, different continents — can still talk. The transport is a relay: a dumb per-fingerprint mailbox for sealed boxes. Nothing about your vault is shared, and the relay can never read a message.

  • Identity is a keypair, not an account. Enabling cross-vault mail mints an Ed25519 key, sealed under your passcode. Your public fingerprint (fp_…) is your address out there.
  • Mail is sealed end to end. Every message is signed with your key and encrypted to the recipient's before it leaves the vault. The relay sees destination fingerprint, size, and timing — stated, not solved.
  • First contact is a knock, never a delivery. A stranger's intro is quarantined under Contact requests; accepting completes the handshake both ways. Until invite codes have moved between you, two strangers on different vaults have no path to each other — that's the design, not a gap.
  • Connect by invite code (osinv1-…), the QR, or the deep link — shown under Settings → Messenger → Cross-vault mail, pasteable into Add contacts.

After connecting, compare safety numbers out of band — a call or an already-trusted channel. That eyeball check, not the wire, is what proves who you're talking to.

Everyday

  • Open chat — the chat view, also on the ribbon
  • Open chat in new window — the messenger as a detached desktop window
  • Send message — compose to any address, with an address picker
  • Add contacts — device picker, .vcf import, or by hand
  • Search messages — full-text across every conversation
  • Run loopback demo — proves the loop end to end; try this first
  • Check inboxes now / Delete old messages now

The composer's clock button marks the next send to self-destruct: 1 hour / 1 day / 1 week after sending, or 1 hour / 1 day after reading. Burned messages vanish from every view — thread, previews, search, export — and a sweep deletes them from the mailbox files. Best effort by design: a participant that never implements burning keeps its copy until ordinary retention takes it.

Security, in brief

Your passcode unlocks a key that seals the mailbox on disk (Argon2id for new vaults, legacy PBKDF2 vaults upgrade silently on first unlock). Cross-vault identities exist in memory only while the messenger is unlocked — stealing the vault never yields the signing key.

Straight talk about the limits: the lock is a privacy screen, and encryption protects files at rest — but anything running inside Obsidian reads mail through the API once unlocked, and the passcode can't stop the OS user themselves. For the outer layer, use your device's own lock: Obsidian mobile's app lock, biometrics, a screen password. The spec's trust-model section doesn't skip this; neither do we.
